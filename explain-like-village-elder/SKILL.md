# 村边老人也能懂——工程对比沟通法

## 触发条件

- 用户问"A vs B 有什么区别"
- 需要向非研发用户解释技术选型
- 用户说"我不懂架构"、"讲人话"、"为什么更好"
- 做架构 / 工具 / 方案对比

## 铁律（必须遵守）

### 1. 禁止术语

不说"架构"、"范式"、"抽象层"、"事件总线"、"MCP 协议"、"乐观锁"。
用户不关心这些词——用户只关心三个东西：

| 用户关心的 | 你要回答的 |
|-----------|-----------|
| 省多少钱（Token） | 每次操作消耗对比 |
| 省多少时间 | 操作步骤数对比 |
| 会不会出错 | 冲突风险 / 丢数据风险 |

### 2. 必须有一句话结论

每段对比结束必须跟一句"村边老人也能懂"的话。

格式：**"以前 X 像做 Y，现在 X 像做 Z。"**

这句话不能含任何英文单词、不能含技术名词、必须是生活中能找到类比的动作。

### 3. 必须有量化对比表

不是"更好"——是"省多少"。每个对比维度必须有数字：

```
| 维度 | 方案 A | 方案 B | 差额 |
```

如果无法精确量化，用保守估算标注"(估算)"。

---

## 标准三段式结构

### 第一段：Token 消耗对比

选一个用户最常做的操作场景，算清楚每次操作的 Token 消耗。

- 列出方案 A 的每个步骤及 Token 数
- 列出方案 B 的每个步骤及 Token 数
- 合计对比，按用户的使用频率（每天/每周）乘以时间
- 结论：省了多少百分比，折合多少钱

### 第二段：效率对比

- 第一次使用的起步步数
- 日常操作的步数
- 多人 / 多 Agent 协作时会不会打架
- 出错了怎么恢复

### 第三段：场景推荐

| 场景 | 用 A | 用 B |
|------|-----|------|

必须基于用户的实际场景做判断，不是泛泛而谈。

## 一句话公式

> "以前 X 像 ______，现在 X 像 ______。"

填空题参考库：

| 技术含义 | 村边老人版 |
|---------|-----------|
| 每次操作需要先搜索再读取 | "像进图书馆，每次都要找书架、翻目录" |
| 打开就知道结构和内容 | "像进自己家，灯一开就知道东西在哪" |
| 多人修改会互相覆盖 | "像两个人用同一支笔写同一页纸" |
| 有锁机制防止冲突 | "像你写字的时候别人不能抢你的笔" |
| Agent 需要每次解释上下文 | "像每次吃饭都要重新介绍自己是家人" |
| 打开就有上下文 | "像回家，不用自我介绍" |
| 文件静态存放 | "像把书放在图书馆架子上" |
| 知识库可以持续维护 | "像在菜地里种菜，种了就长了，长出来就能摘" |

## 示例（Tolaria vs GitHub 作为 SkillHub）

### Token 消耗

场景：Agent 维护 8 个 Skill，每周每个 Skill 更新一次状态、记一条日志。

| 操作 | GitHub 方式（Token） | Tolaria 方式（Token） |
|------|---------------------|---------------------|
| 找到要改的文件 | 先 ls 再读 8 个文件 ≈ 4000 | 打开就知道 ≈ 200 |
| 了解关联 | 读每个 Skill 的 Related 段落 ≈ 3000 | belong_to 自动注入 ≈ 500 |
| 改一个字段 | 全文改再 commit push ≈ 2000 | MCP 一次调用 ≈ 300 |
| 避免写冲突 | Agent 自己检查 ≈ 1000 | 自动拒绝 0 |
| **每周 8 次更新合计** | **≈ 56,000** | **≈ 8,000** |

差 7 倍。

### 效率

| | GitHub | Tolaria |
|---|--------|---------|
| 第一次打开 | 爬目录 → 读文件 → 建索引（3-5 步） | 打开就干（1 步） |
| 找"所有已发布 Skill" | 逐个读 status 字段（8 次） | 一次查 |
| 多人多 Agent 改同一个库 | 后 push 的覆盖先 push 的 | 后写的被拒绝，数据不丢 |

### 场景

| 场景 | GitHub | Tolaria |
|------|--------|---------|
| 一次性发布，半年不动 | ✅ | 大材小用 |
| Agent 持续维护，每周有改动 | ❌ 每次都重爬 | ✅ 省 7 倍 |
| 多 Agent 协作改同一个库 | ❌ 互相覆盖 | ✅ mtime 锁保护 |
| 想 Agent 开箱即懂 | ❌ 每次 prompt 解释 | ✅ AGENTS.md 一次说明 |

### 一句话

**"以前 Agent 干活像进图书馆，每次都要先找书架、翻目录、一页页找；现在 Agent 干活像进自己家，灯一开就知道东西在哪。"**
