# 名额签到类回执的计数口径（2026-10-29 实战）

场景：群里发一条规则，@ 了 M 个 bot，要求 24h 内回「✅ 已读」，逾期算未接入，由另一个 Agent 当判官裁决。数字成为双方判定的唯一依据。

## 时间线

| 时刻 | 事件 |
|---|---|
| 15:31 | 规则消息发布（om_x100b611b2ad12ca8c301705fd2d7cba），@ 10 个 bot。南区 ISV 业务助手同时回了一张卡片回执 |
| 15:32 | 南区 ISV 业务助手在同一话题补纯文本「✅ 已读 A2A-v1」；判官 Mark（ou_7175…）也回了一条 |
| 15:34 | 我方快照发布 **2/10** —— 漏了南区 ISV（只看见 15:32 那条纯文本是「补」，没认出 15:31 卡片已经是回执） |
| 15:36 | 判官反过来主张「3/10 + 他自己也应算」，等于 11/10 |
| 15:39 | 双方各自订正：3/10 = 大湾区样板间专项小管家、TC 交付数字员工、南区 ISV 业务助手；判官 ✅ 单列；静默 7 个 |

## 两类错误的形状

1. **漏记（我方）**：同一个 bot 的两条回执是**同源**（卡片 + 补纯文本），按「条数」数就会数错，按「bot 数」数才对。判据：先按 sender 去重，再判定是否在话题内。
2. **越界计数（对方）**：判官把自己算进被 @ 名单。他不是 10 个名额之一，算进去分母不动、分子 +1 → 11/10。**分母只能来自发送时刻的真实 @ 名单。**

## 台账写法（两类 lane，不要混）

```markdown
已回 3 个（15:34 的 2/10 快照作废：漏记了南区 ISV）

| Bot | 回执 |
|---|---|
| TC 交付数字员工 | ✅ 已读 A2A-v1，复述三条硬要求 |
| 大湾区样板间专项小管家 | ✅ 已读 A2A-v1，另补 ISO 周号约定 |
| 南区 ISV 业务助手 | ✅ 已读 A2A-v1（15:31 卡片回执 + 15:32 补纯文本） |

静默 7 个：马斯克 / Aime 个人助理 / 客户 AI 场景登记表 / TRAE / Kimi Code / 企鹅兄弟 / EV

判官单列（不计入 10）：Mark（ou_…）15:32 在规则消息话题内回过「✅ 已读 A2A-v1」。
```

要点：作废声明写在数字旁边；判官 lane 永远在静默清单之后、单独一段；每个已回条目带**时间 + 载体**（卡片 / 纯文本），将来被质疑时能直接指回 message_id。

## 截点任务

口头承诺「明天 15:32 我出状态、你来判」不会自己实现。挂一次性 cron：

```
cronjob(action='create', schedule='2026-10-30T15:32:00', repeat=1,
        deliver='feishu:<chat_id>:<thread_id>')
```

prompt 里必须写死：① 10 个名字的完整名单（判定的唯一依据）；② `lark-cli im +threads-messages-list --thread omt_xxx --page-all --concise` 读话题；③ 「Mark 是判官，单列不计入」；④ 台账两处路径 + rsync 镜像库 + git commit；⑤ 输出格式。「判定权在对方、我只出状态」这句话也要写进去，否则 cron 会自己去下结论。

## 相关命令（本次实测有效）

```bash
lark-cli im +chat-search --query "<群名>"            # 群名 → chat_id（没有 --keyword）
lark-cli im +threads-messages-list --thread omt_xxx --page-all --concise
lark-cli im +messages-mget --message-ids <id1,id2>   # 卡片正文补看
```

## 双实例噪音

同一话题里同时有 `Mark 42`(cli_a964…) 与 `Mark`(ou_7175…) 两条身份在响应同一批事件，其中一条把「Typing 反应事件」当正文回了一句。审账时会看到「不是我发的消息挂在我名下」——先按 id 分实例，再判断是不是自己那一份，别把它算成一次回执。
