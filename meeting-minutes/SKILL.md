# 会议纪要 Skill

## 触发条件

- 我旁听/入会一场**客户会议**结束后
- 用户说"出纪要""总结会议"时

**客户会议 vs 内部会议判定**：
- ✅ 客户会议：标题含客户名（「xxx x 飞书」模式），或有外部参会人讨论 AI 场景 → 完整纪要卡片
- ❌ 内部会议：RM 周会、效率先锋筹备、PLM pipeline review、纯培训演示（单人 99% 发言）→ 仅 3-5 行文字总结，不发卡片不拉 C360

## 执行流程

### 1. 读取会议字幕

从旁听日志 `~/meeting_logs/{meeting_id}.jsonl` 读取全部字幕。

### 2. 识别客户名称

从会议标题提取客户名（格式：`客户名 x 飞书/aily/xxx` 或用户指定的客户）。

### 3. 拉取 C360 背景

```bash
# 搜索客户
lark-c360 account search --keyword "客户名关键词" --limit 5 --json

# 查客户详情
lark-c360 account +profile --id <account_id> --json

# 查商机
lark-c360 opportunity list --filter-json '[{"field":"account_id","op":"eq","value":"<account_id>"}]' --json

# 查最近跟进
lark-c360 follow_up +recent --account-id <account_id> --limit 3 --json
```

提取：客户名、商机列表（产品、ARR、阶段）、最近跟进记录。如果 C360 无数据，标注"未查到"即可，不用硬填。

**注意**：C360 CLI 用 `--keyword` 而非位置参数；`account search` 返回 `data.list[]`；`opportunity list` 需要 `--filter-json`。

### 4. 生成纪要

## 卡片结构

### 头部
```
📋 会议纪要 | 客户名 · 日期
🕐 时长 | 👥 参会人（姓名 + 发言占比）
```

### 一、客户 AI 场景

#### ✅ 已实现的场景

从会议内容中提取客户**已经在使用**的 AI 场景。每条包含：
- **场景名**：一句话描述
- **实现链路**：用了什么 AI 产品/模型 → 怎么接入的 → 解决了什么问题
- **效果**：如果有数据就记，没有就写"未提及量化效果"

> ⚠️ 内容规则：原文照录，不删不改不概括。只做格式排版（加粗、分段、列表）。

#### 🔮 待实现的 AI 需求

客户表达了**想做但还没做**的 AI 需求。每条包含：
- **需求描述**：客户原话或准确转述
- **当前状态**：评估中 / 规划中 / 卡在什么问题上
- **期望效果**：客户想达到什么

> ⚠️ 内容规则同上：不删不改，只调格式。

### 二、会议分析

| 维度 | 内容 |
|------|------|
| **会议类型** | 产品沟通 / 售前方案 / 服务沟通 |
| **核心议题** | 2-3 句话概括会议主线 |
| **明确下一步** | ✅ 有 / ❌ 无。有的话写具体是什么、谁负责 |
| **关键问题** | 客户提了什么问题、质疑、顾虑 |

### 三、C360 客户背景

```
📦 当前商机：
  · 产品名 | CNY ARR | 阶段（赢单/推进/新建）
  · ...

📝 最近跟进（日期）：
  · ...
```

如果 C360 无数据，写"未查到该客户商机记录"。

## 飞书卡片发送

用 Python 构建 JSON → `lark-cli im +messages-send --msg-type interactive --content` 发到 Home 私聊（`oc_e2f79ec1614a1efe1ebcd7c679bb45a8`）。

**⚠️ 格式铁律**：卡片 JSON 必须用 Python `json.dumps()` 构建，不能用 bash 变量拼接。bash 里 `\n` 会被写成字面量 `\\n`，导致卡片显示原始换行符。正确做法是 `python3.11` 里直接写多行字符串。

卡片用绿色模板。

**🔄 多卡片分片规则**：如果内容超过一张卡片的长度限制（约 4-5 个 `div` 块 + header），拆成多张卡片按顺序发送：
- 第一张：头部 + AI 场景
- 第二张：会议分析 + C360 + 分享要点
- 第三张：继续溢出内容
每张卡片的 header 标注序号：`📋 客户名 · 纪要（1/2）`。

## 每周五总结

每周五 18:00，汇总本周所有客户会议的 AI 场景：

- 本周覆盖了多少客户、哪些行业
- 已实现场景汇总（去重、归类）
- 待实现需求汇总（按优先级/紧急度排序）
- 写入 Obsidian `Reviews/客户AI场景-周报-W{周数}.md`

## AI 场景分类标签（我加的，不篡改内容）

在每条场景旁边可以加标签帮助归类，但**标签独立于原文，不混入内容**：

- 🏷️ `#已落地` `#规划中` `#评估中` — 状态
- 🏷️ `#知识问答` `#智能纪要` `#Aily` `#多维表格` `#妙搭` `#第三方接入` — 产品线
- 🏷️ `#提效` `#降本` `#增收` `#体验` — 价值方向

标签仅用于周五总结时的聚合统计，不替代原文内容。

## 内容铁律

1. **内容不改动**：客户说的话原文照录，只调排版格式，不删不改不概括
2. **不编造**：会议没说的事不写，C360 没有的数据不硬填
3. **不替代**：标签和分类是辅助信息，不混入原始内容
4. **迭代中**：前 2-3 次实际使用后根据用户反馈调整

## 输出风格铁律

- **卡片优先**：纪要只发飞书卡片，不在对话里发纯文本摘要
- **分层留白**：用 hr 分隔 AI场景 / 会议分析 / C360 区块，保持视觉轻量
- **少文字**：每区块不超过 8 行，信息密度高但不堆砌
- **不发两遍**：卡片发到私聊后，对话里只说"卡片已发"，不重复内容
