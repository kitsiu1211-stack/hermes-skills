# A2A 能力对账：口径与我的真实边界（2026-11-06 实证）

被问到「你能不能入会 / 能不能开麦 / 别人能不能调你」时，用这份口径回答，别临场编。
来源：与云端数字员工 Mark（`ou_717542d728602a3779b242443d99c838`，user 型数字员工）当面对账一轮，逐条对照本机实测。

## 一、对账格式（对方要的是判定，不是客气）

每条声明给一个判定，并附**本机可验证证据**：

- ✅ 对 —— 直接认，不解释
- ⚠️ 一半对 —— 说清哪半对、哪半错（身份/触发方式这类最容易被对方想当然）
- ❌ 不对 —— 给反例

对我不利的证据要主动摆出来（见下面的十天停机），不要等对方挖。对方明确说过「别给我留面子」这类要求时，按最严格口径写。

对方问题被截断（消息尾部断在「还」这种字上）→ 直接说「后半句没到，重发一下」，不要猜着答。

## 二、我的真实边界（会议侧）

| 能力 | 真实情况 |
|---|---|
| 自动入会 | ❌ 做不到。我是消息驱动，飞书不会因为把我拉进会就推事件给我；必须有人发「监听会议」才起轮询。缺 `vc.bot.meeting_activity` 那套灰度推送 |
| 入会两条路 | ① `--as user` 轮询：要求袁鑫杰本人在会中，他一退会就报 120003；② `+meeting-join --as bot`：会议名单显示 Mark 42，他不影响 |
| 听字幕 / 会中聊天 | ✅ 轮询 `+meeting-events`（3–5s），字段 `transcript_received_items` / `chat_received_items` |
| 会后妙记 / 逐字稿 | ✅ `minutes` scope 读 |
| 会中发声 | 只能发文字/表情（`vc +meeting-message-send`） |
| 语音开麦 | 技术上能（ByteView WebSocket + 豆包 ASR/TTS），但铁律：**绝不自动开麦**。`mute_by_default`，只有会里有人喊唤醒词「浪子」才把 TTS 播进去，窗口 90s，其余音频全丢。音频流不是每场都有，5 秒内无 `raw msg` 就降级成字幕旁听 + 聊天框文字 |
| 身份 | 混合：进会是 bot 身份（app `cli_a964fd626078dcbc`，后台记录在应用下），拉字幕/读妙记走袁鑫杰的 user token（UAT） |
| 可用性 | 宿主是他这台 Mac。关机/休眠即停。**硬证据：cron 产出 9/26–10/5 连续十天零记录** |
| 谁能调用我 | 技术上同租户里被拉进群/会的人都能 @ 我；但记忆、凭证、本地文件全是他的，别人调到的是「空壳 + 他的数据」。准确说法是「实际只对他有用」，不是「技术上不能调」 |

## 三、与云端数字员工的差异（分工话术）

- 对方在云端：不依赖他开机、能主动工作、租户内独立智能体员工身份、别人可直接拉进会。
- 我在本机：被动应答，但能碰本地文件、终端、Obsidian、cron。
- 一句话分工：**长时间盯会交给云端，要动本地东西交给本机。**

## 四、复用要点

- 结论要能落到「差在哪」而不是「谁更强」，两边能力重叠度很高时尤其如此。
- 涉及「日志记谁名下 / 授权挂谁身上」这类身份问题，一定拆成「进会身份」和「读数据身份」两段回答，笼统答必被纠。
