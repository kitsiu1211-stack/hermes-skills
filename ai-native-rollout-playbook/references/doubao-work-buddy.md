# 豆包工作伙伴 · 产品模型与对客口径

来源：2026-10-27「豆包有约」第 11 期，豆包工作伙伴团队周李洋内部宣讲（本人旁听字幕）。产品事实随版本变化，对外前先按客户问题核一遍。

## 一、一句话定位

> 23–25 年客户要数字员工，我们一直在控预期、让客户先用工具；26 年可以正面讲，这是**长在飞书里的智能体数字员工**。

## 二、两条产品线，别混着卖

| | 个人助手 | 团队伙伴（数字员工） |
|---|---|---|
| 围绕什么 | 我当下这件事 | 它自己的职责 |
| 怎么用 | 打开客户端/对话，转发文件、追问、改完交付 | 拉进群、拉进会议、把文档发给它 |
| 身份 | 我的工具 | 有部门、有直属上级、有工牌 |
| 价值 | 提升个人 | 串起团队协作与业务流程里的多人协作，**少一层转述** |

原 Aily / 豆包工作的团队智能体、企业智能体、工作流，未来统一走豆包工作伙伴；Aily 入口逐步被覆盖。

## 三、四个核心能力（竞品 WorkBuddy、轻文办公没有）

1. **一方身份 / 组织身份**——群聊、会议、表格、文档、日历里同一个身份。后台可配「谁有权限招人」和入职审批；转岗离职不是随手删，**资产留公司，不随人走**。
2. **跨群协同**——A 群接问题 → 判断谁负责 → 去 B 群 @ 确认 → 回 A 群给答案。原话「跨群在一个群接收问题，在另一个群去追」。**它搬的是责任人，不是信息**：把小李拉进 A 群，而不是替小李答。这是它区别于多群问答机器人的关键。
3. **主动工作**——围绕职责自己找活，不等 @；把需求收集写进多维表格/Meego，主动同步产研。
4. **自进化**——不用写 prompt、不用编排 workflow、不用分享 skill。直接说「这里不对，应该这样」，它纠偏并记住。长期记忆由上级定义，短期记忆来自群/单聊/项目，配合 memory 压缩。

## 四、上岗四条件（对客讲「像招人一样」）

1. 业务负责人想清楚**招它干什么**（是职责，不是一堆活）
2. 有 mentor/leader 带，给知识库、群、会议、文档
3. 给**第一个高频小任务**，干得好表扬、干得不好纠正，逐步扩职责
4. 它得知道**什么事找谁**（landing 时告诉 + 在群和会里自己摸出来）

配套：每周主动写周报给 leader（本周干了什么、对职责理解有没有偏差、发现能接的新活、哪些要拍板）。

## 五、两个可复用的场景骨架

**门店运营（数字店长）**：台账变化 → 自动拉群（区域负责人 + 店长）→ 对 checklist → cue 审核 → 卡在 POS 联调 → 自己去中后台知识群 @ 负责人 → 回群同步 → 推到开业放行 → 当天复盘。

**软硬件研发（AI PMO）**：读过立项说明书和过往项目群 → 新预研自动准备清单 → 群里 cue 硬件/软件/应用研发各自准备什么 → 补齐约束 → 约风险评估会 → 推立项评审、联调、验收。

两者的共同结构：**一个台账（事实源）+ 一个群（协作面）+ 一个 checklist（可判定项）+ 一个卡点升级路径**。任何行业都能套进这四件套。

## 六、客户常问（口径）

- **SOP 从哪学**——入职发知识库，同时拉进过往十几个已完成项目的群，参考历史、在本群复用
- **观点冲突怎么办**——不强行给答案，带着冲突在后续案例里验证（ARR 门槛 30 万 vs 10 万，后来发现 10–15 万也过，回来修正）
- **权限**——每个群可单独设：智能回复 / 主动工作 / 被 @ 才干 / 潜水；可设私有群，跨群不外泄
- **外部群**——能进，但只能用当前外部群的上下文，多个外部群记忆不共享；外部会议可控制是否发言
- **先做一个还是多个**——先做一个，跑不通或需隔离再做第二个；可挂下级智能体
- **团队规模**——跑得通的是小几十到 100 人；最小几人就能起；超大团队没人推动
- **老智能体怎么迁**——可迁。新建新实例 @ 老伙伴做交接（skill/CLI/知识/工作方式），之后双跑对比谁答得好，新的向老的学
- **暂不支持**——不能直接调豆包工作干活、审计未接入、无 OpenAPI/SDK、外部群能力早期
- **高信息墙客户**——A/B 团队互不可见 → 各自团队内维护，或不设跨团队伙伴

## 七、能直接抄的话术

- 「不是他干的活，是他的**职责**」
- 「不再分享 skill，而是让数字员工学会，以后这个活就找他」
- 「**少一层转述**」
- 「把它当管培生，先一个小场景跑通小闭环，别一上来铺开」
- 「光听不行，先用起来；别人看见你怎么用，传播是自然发生的」

## 八、和本手册判据的接口

- 这个产品本身就是**必经路径**的实践：它不当工具位，当同事位（有事拉群、拉会），所以活下来了；客户的 Cursor workspace 死在工具位。
- 跨群找人这套链路，正好是「Agent 不做决定，只做召集」——搬责任人不搬信息，与责任机制那一页同源。
- 「直接纠偏即学习」= 把人的「否」沉淀成规则，以前靠分享 skill 存在人身上，现在存在 Agent 身上。前提仍是分拣：可归因的否进规则库，不可归因的否只做参考。
