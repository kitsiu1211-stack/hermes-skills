# 客户 AI Native 落地作战手册

用户是飞书 FDE（前线部署工程师），核心工作是把客户业务流拆开、判断哪段能交给 Agent。本 skill 是**判断框架 + 对客材料规格 + 验证方案**，不是产品介绍。

## When to Use

任一条命中就用：
- 客户问「AI 该切在哪 / 人到底干什么 / 会不会取代人」
- 客户做了一堆单点 AI 工具但用的人越来越少
- 要给老板或客户负责人做一页纸材料、开共创会
- 要设计一个能拿到预算的 POC
- 用户拿客户的会议纪要 / 调研记录来问「这条路该怎么走」

## 一、三根判据（先给判据，再给方案）

1. **可逆性**——做错能一键回滚、重做成本≈0 → Agent；做错要返工几天或赔钱 → 人。
2. **可判定性**——产出能被「是/否」判定 → Agent 主导；只能被「偏好选择」→ 人主导。
3. **必经路径测**——关掉这个 AI，流程会不会卡？不卡只是变慢 = 玩具，迟早被弃用。这一条比任何满意度调查都准，且零成本，先让客户自己回答。

## 二、五条可直接对客说的结论

- 每加一个子 Agent，主 Agent 就多一层丢包。n 个子 Agent 通信成本 O(n²)，最后拿到的是 n 份局部最优摘要，拼起来必然失真。
- 单点工具必死不是员工懒，是**成本在人、收益在部门**——学工具是他的成本，省下的人天是别人的收益。
- 人追责找「谁」，AI 追链路找「为什么」。**两条轨的终点是同一个签规则的人**，缺一条就断：只追链路 → 复盘三次会、规则一条没改；只追责 → 同一个错换个项目再犯。
- 可逆性不是天生属性，是**攒出来的**。高可逆区做厚（零签字）→ 抽检替代全检（建错误率看板）→ 低可逆区变可逆（授权额度上调）。
- AI Native 的标志不是「人人会用 AI」，是**流程里已经没有那个必须手做的环节**。

## 三、两层记忆，别混（这是整套方法论里最容易做错的地方）

人的每一句「不行」都要过一遍分拣机：

| | 特征 | 去向 | 后果 |
|---|---|---|---|
| **可归因的否** | 能量化、说得出为什么（圆角/公差/成本/合规/卖点缺失） | **规则库 · 硬约束** | Agent 下次自动过滤，不再问第二遍 |
| **不可归因的否** | 说不上来、「不够高级」「感觉不对」 | **参考层 · 软记忆** | 只影响候选排序，绝不写成硬规则 |

只喂「否」会养出**另一个老板**：偏好收窄 → 只剩安全牌 → 企业失去差异化来源。三条解药：每轮强制留 10–20% 反直觉方案做对照；让 Agent 定期反问「这几次否的共性是什么」（帮客户把品味结构化，设计团队最缺这个）；发散阶段不吃约束，收敛阶段才用规则。

## 四、老板红队九问（预演过再进会议室）

| 他会问 | 应对 |
|---|---|
| 你这是让我多管事 | 只先卖 3 条便宜的洞察（必经路径测 / 成本在人 / 追链路），机制留到第二场 |
| 谁来当流程所有者 | 承认这需要一个「对规则准确率负责」的人，KPI 从「审了多少件」换成「一次通过率、事故率」 |
| 省的人天变不成我的账本 | 不承诺减员。给两条兑现路径：同人数接更多项目 / 连续两季冻结一个 HC |
| 客户不会因为「链路已修正」就不索赔 | 把归责变成定价：事故预算 + 可撤销授权额度 + 降级而非赔偿 |
| 端到端第一步就要动组织 | 先在一个部门内部跑通，动组织放第三阶段，等数字出来反对成本更高 |
| 你在赌我的品味能被写下来 | 承认只有 20% 可写。所以先做外围（调研/校验/传播/文档），不碰审美 |
| 那些阈值谁拍的 | 「我拍的所以我认」；基线现场实测后一起改一次，改完签字 |
| 我等不了 12 个月 | 给两周的确定性，而不是一年的路线图 |
| 你是不是在给自己争地盘 | 直接答三件事：对你什么好处、对我什么好处、出事谁兜 |

**开场永远是「一个请求 + 一个数字」**：我要求 1 个人两周，把这个环节压到 1/3，然后你再决定投不投。没有请求的汇报，老板只会说「挺好，继续研究」。

## 五、四页一页纸（材料规格）

| 页 | 内容 | 说服对象 |
|---|---|---|
| 1 归因图 | 唯一判据 + 四环节按可判定率重排 + 记忆分拣机 + 偏好收窄风险 | 理性 |
| 2 推进路径 | 用不起来四个真因 + 必经路径测 + 端到端三前提 + 四步推进 | 他们自己的失败经验 |
| 3 责任机制 | 两个物种对照 + 双轨事故图 + 可逆性复利三阶段 + 三条护栏 | 风险偏好 |
| 4 两周验证 | 选环节五条 + 10 天甘特 + 四个指标三档结论 + 失败也有沉淀 | 掏钱的手 |

- 讲解顺序 ≠ 材料顺序：**先数字（第 4 页）→ 再框架（1–3 页）→ 回到数字和失败预案**。
- 第 4 页的基线数字**留空**（虚线下划线占位），现场实测再填。客户看到空白会问，答「我不打算用编出来的数字说服你」——这一句比任何 ROI 预测都值钱。
- 对外材料脱敏：客户名、人名一律匿名化（某+行业+企业）。

## 六、两周 POC 设计模板

**选环节五条，缺一条就不该从这儿开始**：有客观对错 / 高频 / 错了不致命 / 有历史样本 / 客户自己嫌烦。

| 阶段 | 天 | 动作 |
|---|---|---|
| 基线 | D1–D2 | 不做 AI，只做标尺。拿历史三份真实产出逐条标注：条数、错误条数、耗时 |
| 搭建 | D3–D5 | 信息源清单 + 出处强制 + 输出模板 |
| 同题对跑 | D6–D8 | 3 个真实项目，人工版与 Agent 版并行 |
| 判决 | D9–D10 | 盲评（不告诉评审人哪份是 AI）+ 算账 + 结论 |

四个指标：耗时（目标 ≤ 基线 1/3，通过线 1/2）、错误率（≤ 基线，通过线 1.2 倍）、必查维度覆盖、复核返工率（≤20%，通过线 30%）。

三档结论必须写死动作：达标 → 进下一环节追加预算；有条件 → 再两周修那一条链路；不达标 → **立即停**，换环节重测。

投入口径：1 人 × 50% + FDE 1 人，0 采购、0 组织变动。兜底叙事：无论成败都留下**带错误率标注的基线数据集 + 该环节规则库**，下一个 Agent 从这两样长出来。

## 七、陷阱

- **别把「端到端全流程 Agent」当第一版**。主 Agent 变丢包点，客户三个月后得出「AI 没用」的结论。
- **别一次说全九条机制**。老板会认同框架但不会投钱，因为收益还是「员工更快」。
- **别替客户判断值不值**。只报数字 + 给 A/B/C 三档成本选项。开始「劝」就从工具变成说客。
- **别把「加签字人」当答案**。签字面积不降下来（100%→5–10%）就等于没改，客户会当场指出来。
- **别忽视签发人**。端到端会穿过部门边界，没人认账时所有人的第一反应是「我先自己核一遍」，AI 干完人再重干，总工时反而上升。
- 客户现有工具用不下去时，先问「关掉它部门明天会不会停」，别急着诊断员工意愿。
