# 敢忘记忆手术（Dare to Forget）

## When to Use

用户说「敢忘」「整理/审计你的记忆」「看看你的记忆里有什么」「记忆太多了」；或 memory 使用率 > 85% 且存在疑似孤儿/过时条目时触发。目标是主动设计遗忘，不是等满了再压缩。

> 记忆的功能不是完整重现过去（录像机），而是撑起未来的决策（军师）。
> —— Blake Richards, Neuron

## 核心理念

**忘 ≠ 删除，忘 = 提炼**。敢忘不是记忆力差，是知道什么值得记。

一条记忆的价值 = **它改变未来决策的次数**（北极星指标）。如果一条记忆从未影响过任何决策，或连用户本人都不认领，它就是噪音，该忘。

**三条删除线**（先问再删）：
1. **过期货**：带日期的、已失效的信息（模型已换、机制已改、版本已升）
2. **手段类**：过程/技巧/脚本参数/流程步骤——已沉淀进 skill 的，memory 只留指针
3. **孤儿记忆**：从旧会话继承、用户从未确认过的机制细节——**用户说"我不确定" = 最权威的删除信号**

**留下来的是判断类**：用户身份、用户认领的事实、用户纠正过的偏好、影响下次决策的规则。

## 四步手术流程

### Step 1: 亮诊断（术前清单）

按三条删除线扫描当前 memory，列成表格：

| 处置 | 标本 | 为什么敢忘 |
|---|---|---|
| 🗑️ 删（过期货） | ... | ... |
| 🗑️ 归还 skill | ... | 细节已在 XX skill，只留触发句 |
| ✂️ 压缩 | ... | 合并同类，判断保留 |

### Step 2: 批量执行

memory 工具 operations 数组一次原子应用（all-or-nothing）。注意：
- `old_text` 用**短唯一子串**，别用会漂移的整句（系统提示快照可能过期，失败时拿返回的 `current_entries` 重建）
- 手段类压缩时确认对应 skill 里真的有细节，只留触发句/指针
- 带日期的机制若仍在有效期（如"至12月底"），可保留但注明到期点

### Step 3: 亮给用户审 ⭐ 核心

手术收尾后，把「我以为的永恒」条目列给用户，邀请划掉：

> 下面这几条是我以为的永恒，你看有没有其实已经过期、该划掉的？
> 1. ...
> 2. ...

**用户说"不确定/不记得/不知道" → 立即删，不再追问。** 用户本人都不认领的记忆 = 从未影响决策 = 纯噪音。保留用户明确认领的大背景即可。

### Step 4: 汇报前后对比

- 展示使用率变化（如 99.8% → 81%）
- 强调：全程没丢一条用户确认过的事实
- 提议：每月亮一次清单让用户划（可挂 cron）

## 与姊妹 skill 的分工

| skill | 定位 | 触发 |
|---|---|---|
| `memory-management` | 只存 [stated]，入口把关 | 用户问整理/审计 memory |
| `memory-compress` | OptMem 四层金字塔，被动压缩 | 使用率 > 80% |
| **`dare-to-forget`（本 skill）** | 主动设计遗忘，用户审计删除 | 敢忘/记忆审计 |

memory-compress 管"满了挤一挤"，dare-to-forget 管"主动扔垃圾 + 让用户当审计官"——后者才是敢忘哲学。

## 实战案例（2026-09-08）

**术前**：99.8%（2195/2200）。**术后**：81%（1796/2200），两轮手术 6 处清理：

第一轮（自删 5 处）：
- 「DeepSeek V4 Pro 上下文 1M」→ 已切 flash，过期货
- 会议旁听脚本坑、文章分析流程 → 已在 skill，只留触发句
- 钢人四步说明、视觉模型元信息 → 压缩

第二轮（用户审计删 3 处孤儿）：
- 标签五类、保护期/ISV、协作场景机制 → **用户说"这三个是什么我都不确定" → 直接删**
- 保留大背景：「2026-08 字节重组」——用户认领

## Pitfalls

- **别把「用户说过一次的话」当永恒**：旧会话继承的机制细节，若从未被用户二次确认，默认孤儿
- **删前确认 skill 里有备份**：手段类记忆归还 skill 前先查 skill 内容是否覆盖，避免两头丢
- **不在用户不确定时替用户脑补**：用户说不确定 = 删，不是去旧会话翻出来解释给他听
- **压缩后不追加时间戳条目**：使用率本身（<80%）就是防重复压缩的闸
