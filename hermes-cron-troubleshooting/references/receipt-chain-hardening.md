# 回执链路加固与自测（2026-10-28 实战）

外部哨兵/回执链路的设计见 `external-sentinel-receipt.md`。这一页只讲**怎么保证它在第一次实战时不掉链子**——回执链路的失效是静默的：发不出去的时候，观察方看到的是"任务没跑"，你会被判漏跑，而你这边可能连报错都没留下。

## 一、`selfcheck` 通过 ≠ 真实路径可用（本次最贵的教训）

当晚首次实战是周五 18:00 的周复盘回执。上线前跑的 `cron_receipt.sh selfcheck` **返回 ok、真实进群了**，看着链路是通的。但 `selfcheck` 走的是独立分支，`ok` 分支里有一行：

```bash
MSG="✅ ${TASK} ${PERIOD}${SUF:+（$SUF）}"
```

`${SUF:+（$SUF）}` 里的**全角括号会被 bash 当成变量名的一部分**，在 `set -u` 下直接：

```
line 19: SUF）: unbound variable
```

**它不依赖 cron 的缺失 locale，普通交互 shell 里一样炸**（与 SKILL.md 里那条 `$NO，` 的 C-locale 坑不同，这条是参数展开内部的全角字符）。后果：18:00 真的跑完周复盘，`✅` 一行也发不出去，19:07 被判漏跑。

三条可迁移结论：

1. **自检必须走和真实动作同一条代码路径。** 一个只在旁支分支上验证过的 selfcheck，等于没有自检——它证明的是"网络和凭据通"，不是"这条消息发得出去"。
2. **中文/全角标点不要写进参数展开内部**（`${X:+…}` / `${X:-…}` / `${X#…}`）。要拼就拼出来：
   ```bash
   SUFFIX=""; [ -n "$SUF" ] && SUFFIX="（${SUF}）"
   MSG="✅ ${TASK} ${PERIOD}${SUFFIX}"
   ```
3. **幂等键也要按同样方式拼**，别写成 `${SUF:+-$SUF}` 之外的变形——顺手统一成两次赋值最保险。

## 二、零噪音自测：假 CLI + 独立 HOME

回执链路的自测难点是"测一次就在群里发一条假回执"，观察方会被污染。做法是给 `lark-cli` 做个假壳，把 `HOME` 指到临时目录（日志也跟着落到临时目录）：

```bash
rm -rf /tmp/rcpttest && mkdir -p /tmp/rcpttest/.hermes/cron /tmp/rcpttest/bin
printf '#!/bin/bash\necho "{\\"ok\\": true}"; echo "ARGV: $@" >> /tmp/rcpttest/argv.log\n' \
  > /tmp/rcpttest/bin/lark-cli
chmod +x /tmp/rcpttest/bin/lark-cli
export HOME=/tmp/rcpttest PATH=/tmp/rcpttest/bin:$PATH

S=/Users/bytedance/.hermes/scripts/cron_receipt.sh
bash -n $S && echo "syntax ok"
bash $S ok   "周复盘" "2026-W44"
bash $S ok   "周复盘" "2026-W44" "补跑"
bash $S fail "周深读" "2026-W44" "state.db 写入失败"
bash $S skip "Skill同步" "本周非执行周"
cat $HOME/.hermes/cron/receipts.log      # 四条形态逐条核对
grep -o 'rcpt-[a-zA-Z0-9-]*' /tmp/rcpttest/argv.log   # 幂等键
```

验收标准：**四种形态的中文文本、期次、幂等键全部逐字正确**，且群里一条噪音都没有。任何"只在真群里试一次"的验证都会留下观察方要处理的假信号。

## 三、轮空周 `⏭` 必须是脚本动作，不能靠模型记得发

双周任务（偶数周执行 / 奇数周轮空）最容易漏的就是轮空周的 `⏭`：真任务在奇数周"静默结束"，模型很可能连回执一起省了。观察方看到的是一整周的空白。

方案：`scripts/biweekly_skip_guard.sh` + 两个 `no_agent` cron（周五 10:40 / 周一 09:40，晚于真任务、早于判定时刻）：

- 非双周日 → 静默；偶数周 → 静默（✅/❌ 由真任务负责）
- 奇数周 + 本期日志里没有 `✅`/`❌`/`⏭` → 补发 `⏭ <任务名> <期次> 本周非执行周`
- 已有任何回执 → 退让，不重复发（日志匹配 + `rcpt-skip-<任务>-<期次>` 幂等键双保险）

**六个自测用例（缺一不可，`BIWEEK_DOW_OVERRIDE` / `BIWEEK_WEEK_OVERRIDE` 提供）**：

| # | 场景 | 期望 |
|---|---|---|
| 1 | 周三（非双周日） | 静默 |
| 2 | 周五 + 偶数周 | 静默（不抢真任务） |
| 3 | 周五 + 奇数周 + 无回执 | 发 `⏭ … 2026-W45 …`，周号正确 |
| 4 | 场景 3 再跑一次 | 静默（幂等） |
| 5 | 周一 + 奇数周 | 发另一个任务的 `⏭` |
| 6 | 周五 + 奇数周 + 已有 `✅` | 静默 |

**做可测日期逻辑时，`date` 的每一处输出都要可覆盖**：`%u`（星期）、`%V`（周号）、`%G`（ISO 年）分别给一个 `*_OVERRIDE` 环境变量。第一次自测就踩到——只覆盖了周号没覆盖星期，脚本在周三跑直接走了 `exit 0`，看起来"静默正确"，其实一个用例都没验证到。

## 四、`⏭` 必须带期次

最初写成 `⏭ <任务名> 本周非执行周`（无周号）。观察方按「任务名 + 期次」匹配，没有周号只能靠"翻历史推断这周是不是轮空"，等于把确定性又还给了人猜。改成 `⏭ Skill同步 2026-W45 本周非执行周`，期次由脚本按 ISO 周号生成——调用方不用改。**这条是我单方面改的，改完要主动报备观察方**（契约类字段的改动，改完不报备比不改更糟）。

## 五、和观察方核对"同一件事的两种写法"

观察方锁的口径是"偶数周执行、奇数周必发 ⏭"。我这边两个 cron 的 prompt 写的是：

- Skill 同步：`检查当前是否为双周周五（ISO 周号为偶数），如果不是则静默结束`
- 赢单雷达：`只有【偶数周】才继续执行完整流程；【奇数周】直接静默结束`

**读 prompt 原文逐条核对**（不是凭印象说"应该一致"），确认无漂移后才敢锁死判定口径。凡是跨 Agent 的契约（期次格式、回执形态、判定时刻），都要落到"两边各自的实现原文长什么样"，而不是"两边口头说的差不多"。

## 六、边界要主动说清（别把脚本兜底吹成万无一失）

脚本兜住的是「模型漏发 / 任务静默跳过」，兜不住「整机睡死」——机器 09:40 前没醒，兜底脚本同样不跑，`⏭` 一样发不出。这句话必须在交付时先讲明，并明确"这种情况照样按漏跑判，我认"。**先给边界再给能力**，比事后解释便宜得多。
