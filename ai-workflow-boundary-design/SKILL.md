# AI 落地人机边界设计

给企业做 AI 落地咨询时的**框架层**：不是问"哪个环节能加 AI"，而是先切"哪些产出可判定、哪些只有偏好"，再定"出错谁认账"，最后定"怎么推"。适用于 FDE 前置咨询、方案汇报、客户反问"这跟现在有什么区别"的场合。

## When to Use / 何时触发

- 客户说"我们每个环节加个 Agent / 主 Agent 协调子 Agent"
- 客户说"员工不愿意改变习惯""工具用的人越来越少"
- 客户说"AI 做完人还要再审一遍，跟现在没区别"
- 客户说"不敢把业务直接交给 Agent，出错了没人担责"
- 需要把一轮深度讨论收敛成可给客户看的材料（→ 出三页海报，见下文）

## 六条核心判据（可直接对客户说）

1. **可逆性切分**：做错重做成本≈0 的交给 Agent，做错要返工几天或赔钱的交给人。
2. **能判定 vs 只有偏好**：产出能被「是/否」判定 → Agent 主导；只能被「偏好选择」→ 人主导。招聘能自动化、设计不能，差别就在这（考试 vs 选美）。
3. **少 Agent + 强共享上下文**：每多一个子 Agent，通信成本是 n²，主 Agent 成为丢包点。上下文放在共享底座（飞书文档/群/纪要），不在 Agent 之间传话。
4. **可逆性是攒出来的**：不是静态属性。每改一条规则，可逆性上一格；可逆性上去了，授信额度才敢放开。→ 客户"我现在不敢用"可翻译成"先把高可逆区做厚"。
5. **人追责，AI 追链路**：人的失败单位是一次判断（找到"谁"），AI 的失败单位是一条链路（找到"为什么这么判断"：上下文够吗/来源可信吗/规则有漏洞吗/越权了吗）。但**追链路≠不追责**，链路追完必须落到签规则的那一个人，否则"复盘三次会，规则一条没改"。
6. **必经路径测**：关掉它的 AI 权限，流程会不会**卡死**（不是变慢）？卡＝在流程里；不卡＝玩具，迟早被丢。

## 五段框架

### 1. 切在哪（归因）
按可判定率给环节排序（例：产品定义 85%、概念发散 70%、建模渲染 60%、偏好决策 20%），而不是按部门排。每环节标主导方 + 灰条显示"AI 能吃多少"。

发散/收敛分两态：**发散阶段不吃约束**（先野蛮生长 20 个方向），**收敛阶段才用规则过滤**。

### 2. 记忆分拣（可归因 / 不可归因）
人的每一句"不行"必须过一遍分拣：
- **可归因的否**（圆角、公差、成本、合规、卖点缺失、家族语言冲突）→ 写进**规则库**，硬约束，下次自动过滤。
- **不可归因的否**（"不够高级""感觉不对"）→ 只进**参考层**，软记忆，影响排序但绝不写死。
- 风险：只喂"否"会养出"另一个老板"，偏好收窄、只剩安全牌。解药三条：每轮强制留 10–20% 反直觉方案做对照；让 Agent 定期反问"这几次否的共性是什么"（帮客户把品味结构化）；发散阶段不加载规则。

### 3. 谁认账（责任机制）
按可逆性分三层，**签字面积从 100% 压到 5–10%**：

| 层 | 占比 | 机制 |
|---|---|---|
| 可回滚 | 60–70% | 零签字，错了回滚重跑，成本进运营 |
| 可发现 | 20–30% | 不事前审，事后抽检 + 错误率看板 + 超阈值自动降级 |
| 不可逆 | 5–10% | 人签，且只签这一小块 |

关键区分：**"加签字人"是假 AI Native**（审核率仍 100%，只是换了个人）；真机制是压签字面积 + 换审核对象（审规则而非审产出，O(n)→O(1)）。

配套三条护栏：全程留痕（Agent 能自证每一步）／**额度制不是审批制**（授权+上限+可撤销，像信用卡）／事故预算（风险可定价才敢授权）。Agent 不能赔 → 用**预付（预算池）／冗余（并行校准期）／降级（收额度回滚规则）**替代赔偿。

组织落点：必须长出**流程所有者**——KPI 从"审了多少件"换成"一次通过率、事故率、降本工时"。

### 4. 怎么推（推进路径）
单点工具必死的四个真因（都比"员工懒"更准确）：
1. 优化的是**汇报速度**不是交付效率（汇报低频、非瓶颈，天花板低）
2. **成本在人、收益在部门** —— 个人账上是负收益，理性人会放弃
3. **交付物没变**，下游工时没降（内卷式 AI）
4. **不在必经路径上**（合规/交付/评审不依赖它）

端到端能卷动人，但三个前提缺一就翻车：**真的更快**（否则全组受罪、怨气集中）／**第一次上手零学习成本**（做他本来在做的事，不是学 prompt）／**先有一个普通人跑通的可见战绩**（IT 部门跑通的不算）。

四步推进：选全组**最烦**的那件事 → 单点跑通做出可复述的数字 → 把交接串成端到端（关掉会卡）→ 用法快照扩散（每周贴"我怎么问的、它怎么回的"，只贴作业不讲心得）。

**裹挟对象别搞错**：执行者看到战绩会自己挤进来；真正卡流程的是**每个环节的签发人**。

### 5. 收口一句
> AI Native 的标志不是"人人都会用 AI"，是**流程里已经没有那个必须手做的环节**。别问"怎么让员工愿意学 AI"，问"哪个环节还非得人动手"。

## 交互习惯（这个用户的偏好）

- 长分析后常会说"**收敛一下你发的内容**"→ 答完深分析主动补一段"四句话收敛版"，别等他要。
- 框架最终要**落成图**（"做一个图，让企业一眼看到"）→ 分析到闭环时直接出 PNG，不要只问"要不要出图"。
- 用户会追问"**这跟现在有什么区别**"这类反驳——先承认那个答案是错的，再给真机制，别辩护。

## Pitfalls

- **别按环节切人机**（"第一环节人做、第二环节 AI 做"）——设计/创意流程本来就是发散-收敛循环，按环节切必然打架。按可逆性切。
- **别让主 Agent 做协调者**。它只会变成丢包点。主 Agent 只做三件机械事：守版本化基线、算变更影响面、卡未评审闸门。
- **别替客户"放大影响"劝老板**。Agent 一旦开始劝，就从工具变说客，被识破后所有提醒失效。正确动作：量化（影响 3 个已定稿环节、2 份已发提案、约 6 人日）+ 给 A/B/C 三档成本选项 + 把"改需求"和"改标准"分开（"这一条写在你 v1 签字的标准里，现在要改实现还是改标准本身？"）。
- **别把"加签字人"当答案**——客户会立刻反问"这跟现在有什么区别"，因为默认了全流程都要签。必须先说清签字面积 100%→5%。
- **别把 AI 生成图当生产级渲染**。概念图（AI 生成）和生产级渲染（KeyShot 批处理 / Rhino+Grasshopper / Rhino.Compute 走脚本或 MCP）是两件事，混谈会被工程师当场打回。
- 客户老板发散是常态：配**沙盒分支**（随便改，改在分支上，说"采纳"才合并），别用流程拦。

## 复用到别的客户
判据与责任机制行业无关；换客户只换三样：环节名、可判定率数字、客户自己的原话（"不够高级"这类词换成他们真实说过的）。不要把某一家客户的流程结构当模板照搬。
