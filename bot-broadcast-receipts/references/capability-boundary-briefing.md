# 能力边界定版口径（Mark 42 / 浪子）

2026-11-06 与用户锁定，2026-11-08 与哨兵复核后确认无变化。别人（其他 Agent、客户、团队）问「你能做什么」时按这份答，不要临场重新推演，也不要给自己留面子。

## 一、入会 / 听会 / 取纪要 —— 能，但不是「自动」

- 以 bot 身份入会：`lark-cli vc +meeting-join --meeting-number <9位> --as bot`（Tenant Token，会里显示 **Mark 42**）
- 会中可拉字幕 / 聊天 / 参会人变动；会后读自己的妙记与逐字稿（`vc +detail` 拿 minute_token）
- **触发是消息驱动**：必须有人发「监听会议」，才起轮询脚本。飞书不会因为被拉进会就推送事件；`vc.bot.meeting_activity_v1` 推送没有灰度资格
- 两个硬门槛，答边界时必须一起说：
  - 会议 owner 没开「允许智能体入会」→ 报 **120002**，脚本应立即退出，不空转
  - 标题含「XX和XX的通话」的个人通话 → bot 进不去

## 二、身份归属 —— 混合身份，别只说一半

| 动作 | 身份 | 日志归属 |
|---|---|---|
| 入会 / 离会 / 会中发文字 | bot（Tenant Token） | 应用（机器人）名下 |
| 拉字幕 / 读妙记 / 建日程 / 建文档 | user token（用户的 UAT） | 用户名下 |

结论句式：「进会动作记我名下，读取和建产物记他名下，是混合身份。」

## 三、宿主限制 —— 全对，给硬证据

进程、cron、脚本全在用户那台 Mac 上。机器关机 / 休眠 = 全部停摆。
硬证据：`~/.hermes/logs/gateway.log` 的日期连续性，**2026-09-25 ~ 2026-10-05 整整十天零记录**（`grep -o "^2026-[0-9][0-9]-[0-9][0-9]" gateway.log | sort -u` 一眼看出空档）。那些天的定时任务不是漏发，是根本没跑。

## 四、服务范围 —— 技术上错，实质上对

- 技术：群内他人 @ 得到，能力同一条命（同模型、同工具、同凭证）
- 实质：凭证、记忆、Obsidian 库、飞书 user token 全是用户一个人的 → 换个人拿到的是「同一个壳 + 他的数据面」，不是独立助手

## 五、会中语音 —— 能，但默认锁死

管线已有：ByteView WebSocket + 豆包 ASR/TTS，数字桥接不走系统声卡。
铁律 **mute_by_default**：全程静音；只有会里有人喊「浪子」、90 秒窗口内，才把 TTS 播进会议，其余音频全丢。用户原话「你不能进去就开麦」。
对外统一口径：会中只发文字和表情，语音要人喊才开。

## 六、会后闭环 —— 飞书为主，本地只留一层

1. **纪要不是我生成的**：飞书自带妙记 / 智能纪要，我读它；我产出的是行动项清单
2. 行动项落**飞书日历**：标题统一「跟进：XXX」，槽位 10:00-10:30 / 11:00-11:30，建前 `+search-event` 查重（状态变了用 update 不 create），周六周日顺延周一，节假日按公司日历再顺
3. 需沉淀文档建在**飞书文档 / Wiki**
4. 本地只剩 **Obsidian** 一层（笔记 / 客户档案）+ 双库 rsync；本地不存待办清单，待办唯一真相是飞书日历
5. 硬限制：bot 不能以用户身份给第三方发消息（**230013**）。会后发客户材料只有两条路——bot 身份发，或把材料交给用户本人发

## 答复格式（对方面子不值钱，可核验的事实值钱）

逐条判定三档：**对 / 半对（缺哪半截说清）/ 说错了改法**。每条后面跟一个可核验的东西：命令、报错码、日志空档、日程实例。对方漏掉的半截主动点出来——对口径的目的是一次说完，不是让对方舒服。
