# 主动遗忘设计（敢忘）— 从「满了才压缩」到「写入时设计遗忘」

缘起：2026-09-08 与用户讨论 Today.ai 文章（齐俊元重启）中的「敢忘」概念，脑科学佐证 Blake Richards 发在 Neuron 的论文：记忆的功能是撑起未来决策，不是完整重现过去（录像机 vs 军师）。用户认可「AI 应记住习惯 + 历史上下文，用于推动工作」，但追问：敢忘落到 Hermes 的 memory 机制上，策略怎么定？

结论：现有 memory-compress / memory-management 是「被动遗忘」（满了才压缩、入口把关 = 省空间策略）；敢忘要求「主动设计遗忘」（每天顺手扔垃圾 + 定期断舍离，让记忆一直好用）。差距 = 一个等房间堆满再请保洁，一个保持房间好用。

## 四设计动作

**① 写入时定保质期（核心）** — 不是删除时再纠结
每条记忆写入时先问「多久过期」：
- 瞬时（对话完就忘）：临时数字、一次性结论 → 根本不进 memory
- 时效（几周~几月，**必须带到期标记**）：带日期的事件（如「标签五类 8/21 上线」「180 天 C 级建联」「保护期 30 天」）→ 到日子自动失效或被顶掉
- 永久（身份/偏好/铁律）：用户零技术背景、说一遍就够 → 才配占永久位置
对齐 Today.ai 的三档生命周期（用完即弃 / 时效 / 长期习惯与目标）。

**② 小遗忘成为日常，大扫除只是兜底**
每次写入新条目，顺手问「哪条旧的该让位了？」（类比大脑睡眠时突触修剪）。只靠 80% 触发的月度大扫除会长期逼近容量上限（实测长期停在 99%）。

**③ 敢把「用户变了」当一等事件 — 季度记忆审计**
敢忘的终极形态不是 AI 自己删，是 AI 定期把 top 条目亮给用户：「这是我以为的永恒，哪些过期了？」用户业务/角色变化（如转产线、从销售到带教）后，旧记忆会一直推用户走老路。每季度把记忆条目列给用户划掉过期项。

**④ 北极星指标：记忆的价值 = 它改变未来决策的次数**
一条记忆写进去到现在从未影响过一次决策 → 枝节，该忘。写入前过闸：「这条会让我下次做出不一样的动作吗？」不会 → 不进。
