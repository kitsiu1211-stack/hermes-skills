# AI 之间为什么不需要自然语言

解释这条协议为什么成立的底层机制。用户问「AI 跟 AI 到底靠什么交流」时用这份，别现编。

## 一句话

模型内部的「思考」是一串高维向量，说出口等于把它压成离散的词。所以两个 AI 用自然语言对话，等于压缩一次、解压一次，每次都有损。

## 画面

两个顶级工程师站在同一张图纸前，中间只有一条电话线，只能说话不能看不能指。A 看完用语言描述，B 听完重画一遍。会话说十轮，最后那版跟原图已经不是一回事。

## 机制

- 模型计算时的状态是几千维向量，同时编码大量关系
- 输出时要摊平成线性的 token 序列，从固定词表里选
- 接收方再把 token 重新扩展成自己的向量

向量 → token → 向量，两次投影，两次信息损失。这跟 agent 聪明不聪明无关，是接口形状决定的。

## 三条替代路径（成熟度差别很大）

| 路径 | 做法 | 现状 |
|---|---|---|
| 直接传中间状态 | 共享 activation / KV cache，不走词 | 研究阶段。跨厂商模型打不通，且向量无法审计，出错没人看得懂错在哪 |
| 不传话，传台账 | 双方读写同一份结构化状态，不对着说话 | **今天就能落地**，协议本体的基础 |
| 结构化接口 | 交换对着同一份定义表的 JSON（如 MCP） | 主流做法，代价是得先建本体 |

可引用的两项工作（已核对标题，arxiv 可查）

- 《Training Large Language Models to Reason in a Continuous Latent Space》（Meta，Coconut）—— 让模型在连续向量空间里推理，不先转成词
- 《DroidSpeak: KV Cache Sharing for Cross-LLM Communication and Multi-LLM Serving》—— 跨模型直接共享中间计算缓存

## 对方能听懂的类比

同一个办公室的两个老手，明明可以直接看同一张表，却非要一个人念、一个人记。念的人省事，记的人受罪，第三人拿到的已经是二手。

## 落到工程上的四条

1. 别做 agent 之间的对话链。五个串起来，第五个拿到的是转述的转述
2. 先设计共享状态，再把 agent 写成读它、写它的函数。判据是能不能从库里重放一次运行
3. 传指针不传摘要。给 ID、原始记录、规则版本号，别给「上一环节总结了三点」
4. 自然语言只留两个位置。跟人说话的地方，和事后要追责的地方

## 顺手可用的成本账

每一跳自然语言都要把上下文重新序列化一遍。链越长上下文越胀，延迟越高，出错概率越大。这解释了为什么堆了五个 agent 的系统经常不如一个上下文喂饱的单 agent，多出来的四个主要在互相制造噪声。

一句话话术。**agent 之间不该开会，该共享台账。开会是给人用的，因为人会遗忘、会误解、需要达成共识。**
