# REA（Reverse Engineer Anything）尽调实例 · 2026-10-26

开源爆款类项目的评估范本。与 `jev-typesafe-2026-09.md`（闭源托管模型）互补：那是"官方口径 vs 实测边界"，这一份是"**热度是真的，但增量没你想的大**"。

## 一句话定性

给 Coding Agent 接上一整套逆向工程工具的 MCP server + CLI。用户说一句"这个 App 的搜索怎么做，用 TypeScript 复现一遍"，Agent 自己调 Ghidra / Hopper / IDA / JADX / Electron 解包去查，带证据链回来。

人话类比：以前逆向是一个拿放大镜啃反编译代码的人；现在多一个会跑腿的实习生，你说查什么，它把箱子全翻了，回来告诉你哪几份证据能对上。

## 批评面（结论的真正来源）

HN 340 条评论里，最刺的一条被反复问：**"这跟我直接让 Claude 装个 Ghidra 有什么区别"**，下面有人直接回 "worse"。

最准的一条回答：它服务的是**本来就没有逆向方法论、不知道该装 Ghidra 的人**。已经有自己脚本和工作流的人，增量有限。

另一条高赞很刻薄：很多人真正想要的是"感觉自己逆向了一个软件"，而聊天机器人特别擅长让人产生这种感觉。

还有一条独立实测值得记：有人用本地小模型（Qwen）直接指挥 Ghidra CLI 完全跑飞，换 REA 后能推进——**说明它的价值在"把工具链和判断步骤固化成提示"，不在模型能力**。

官方 demo 全是干净封闭场景（小游戏、计算器、剪贴板），**没有任何人公开拿它啃大型脏乱的商业软件**。

## 两个必须点出来的风险

1. **数据出境**：README FAQ 自述"本地分析，但工具结果交给 Agent 的模型提供商，对方有自己的数据政策"。对金融/政企客户是硬伤，反编译产物里常带完整业务逻辑。
2. **法律边界窄**：DISCLAIMER 只允许分析"你拥有或获授权"的软件。中文传播口径已经是「微信、支付宝、抖音惨遭毒手」（虎嗅 2026-10-10 标题，正文 curl 抓不到，仅标题可见）。这类叙事在客户安全合规部门眼里等于红旗。

## 对飞书销售 / FDE 身份的输出结论

- **不在客户面前推这个工具**。飞书卖合规与信任，"能逆向一切"一句话就能把会开成事故。
- **借它的方法论，不借它的产品**。客户说"我要做一个跟 XX 一样的"，痛点是当场讲不清 XX 怎么做的；REA 的核心动作是**先建证据链再动手实现**，与推的 AI 落地路径同构。
- 可以直接问客户的一句：**"你希望做到像谁，你手上有那个东西的合法使用权吗"**。前半句是需求，后半句是风险。
