# 会后跟进：把纪要里的「用户自己的待办」落成飞书日历日程

纪要卡片发出 ≠ 任务结束。**用户本人的待办要立刻逐条落进他的日历**（别人的待办不建），否则他会说自己忘了跟。本页是 2026-10-16「飞书信息管控」一场（快造 HR 团队，20 分钟）实测走通的完整口径。

## 一、先分类，再决定建不建

| 待办归属 | 处理 |
|---|---|
| 用户在会中亲口答应的（「我整理一下」「我尽快」「我发给你们」） | ✅ 建日程 |
| 会议明确派给他的下一步（对方要求「今天下班前给」） | ✅ 建日程 |
| 客户/他人自己的动作（HR 内部对齐、客户走 IT 评估） | ❌ 不建，写进卡片正文即可 |
| 纯知识分享型会议、无个人动作 | 不建，但汇报里要写明「本场无你的个人待办，未建日程」（0 条也要说） |

## 二、命令（已实测）

```bash
# 1) 长描述先落盘，绝不内联进命令（中文多行 = 引号地狱）
#    write_file /tmp/desc1.md：
#    📹 来源会议：飞书信息管控（2026-10-16）
#    📋 待办详情：<从纪要提炼的完整待办，含客户名/负责人/关键背景/客户原话要求>
#    备注：<对客口径提醒，如「内部文档发客户前先确认可发性」>

lark-cli calendar +create --as user \
  --summary "跟进：整理商业专业版安全能力明细发快造" \
  --start "2026-10-16T16:00+08:00" \
  --end   "2026-10-16T16:30+08:00" \
  --description @/tmp/desc1.md --json
```

- `--summary` 只写**「跟进：<主题>」**短句（不含时间/地点/人物），背景与要求全部进 `--description`。
- 时间必须带时区偏移 `+08:00`。
- 时间优先级：① 会上说了具体时间 → 用它 ② 只说了「明天/周五/下周」→ 用那天 **10:00–10:30** ③ 什么都没说 → **会后第 2 天 10:00**，description 注明「⏰ 时间待定，可在日历中改期」。
- **工作日铁律**：周六周日一律视为非工作日，命中周末就顺延到下一个工作日（用 `datetime.date.fromisoformat(d).strftime('%A')` 或 `weekday()` 判断，≥5 即周末）。实测 10-16（周五）的「会后第 2 天」落在 10-18（周日）→ 顺延到 10-19（周一）。
- 「今天下班前」这类当天承诺**不要**顺手推到下周 —— 建当天 16:00–16:30 这一段，他才有机会在承诺窗口内做完。

## 三、建完必须验证：`+search-event` 要显式给 `--page-size`

```bash
lark-cli calendar +search-event --as user --query "跟进" \
  --start 2026-10-16 --end 2026-10-24 --page-size 20
```

🚨 **默认页大小会截断**：实测建了 4 条，`--query "快造"` 只回 3 条，差点误判「有一条没建成」再去重复建一条。用 `--query "跟进" --page-size 20` 拉全量、逐条比对 `summary` 与本次建的一一对应。

同主题日程已存在（官方培训、别人已建的会）→ 跳过不建；事情进展了就 `+update --event-id` 改写那条，别新建第二条。详见主文件 Pitfalls 里「同一客户/事项的跟进日程」那条。

## 四、汇报模板（缺一块用户就要问）

```
📅 已创建跟进日程（N 项）：
✅ 跟进：整理商业专业版安全能力明细发快造 → 今天 16:00
✅ 跟进：输出快造安全方案（策略中心+版本升级）→ 周一 11:00
...
🔍 我已帮你找到的材料：<链接>
⚠️ 没做到的：<如 C360 被网关拦截（code 100001）拿不到客户情报 + 重试选项>
```

## 五、⚠️ 顺手帮用户找材料时的红线

会中用户答应「给你们发文档」→ 你 `docs +search` 找到的**多半是内部文档**。实测搜「商业专业版 安全能力」「策略中心 报价」拿到的是：内部版飞书版本对比、`飞书安全合规增值服务定价政策（同步版）`、灰度开通流程。

- ✅ 做法：把链接列给用户，**并列一句「发客户前请先确认可发性，或换安全售前的对客版」**。
- ❌ 不要自己替他对客转发、不要声称这些就是「对客材料」。
- 内部材料直接外发是事故；**可发性判断权在用户**，你的职责是把风险点摆到他面前。

## 六、边界情况

- **C360 报 code 100001** = 网关安全检测拦截，**不是授权过期**，别连续重试；在汇报里如实写「没拿到 CRM 情报」+ 重试选项，绝不编造客户商机/席位数据。
- 客户名以**会议标题**为准；标题没写客户名时，用字幕里当事人自述的身份（例：`罗承意(Roy)` 自述「我是负责 HRBP 团队」）定位到人，但不要凭字幕里的案例引用反推客户名。
