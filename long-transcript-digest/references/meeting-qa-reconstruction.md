# 单场问答还原 / 对客答疑复盘（输出变体）

**触发**：用户看完（或错过）一场客户会后问 —— 「对方提了什么问题？」「某某为什么这么大意见？」
「你整理一下某某分享的聊天内容」。要的是**问答还原 + 情绪归因**，不是产品能力纪要，也不是会议流水账。

取自 2026-10-14 一场「飞书项目 vs Jira」工具选型会：客户逐项逼问、内部售前在私聊里说「我想跟他们干起来了」，
用户错过会议、要求还原两边到底发生了什么。

---

## 0. 范围铁律（先定界，再检索）

用户点名「现在这场会议 / 这一场」时，**只查这一场**：会议 JSONL + 该场同步群 + 相关同事当日私聊。
不要顺手扩散到别的客户群、别的会议、历史会话——范围错了会被当场纠正，白跑一轮。

## 1. 素材三源，缺一不可

| 源 | 拿什么 | 怎么拿 |
|---|---|---|
| 会议字幕 | **对方的问题几乎全在这里**（逐条可引用） | `~/meeting_logs/<id>.jsonl`，去重 + 按 `time` 排序后按说话人分段读（用 `scripts/transcript_paragraphs.py`） |
| 会中聊天 / 同步群 | 客户贴的**评估表、需求清单、文档** | 图片只在同步群里：`im +messages-resources-download` 下载 → **vision 读成文字** |
| 内部同事私聊 | 他的真实情绪（会上他不会说） | `contact +search-user` → `im +chat-messages-list --user-id` |

取数的命令与坑（`messages-search` 缺 scope、`--page-size` 过大返回 0 条、会中聊天框只回表情短文本）
见 `lark-cli` → `references/chat-evidence-retrieval.md`，别在这里重复摸索。

## 2. 输出结构（顺序别搞反）

1. **一句话结论**先给（「是呛，但呛的不是功能，是打法」这种判断句），别铺垫
2. **对方提了什么问题**——分两段：
   - ① **评估表 / 清单**：客户自己给出的评估项逐条列出（这往往就是「问题清单」本体，读图得来）
   - ② **会上实际逼问的问题**：表格 `问题 | 我们给的答案`，按时间顺序，一条一行
3. **情绪归因**（用户问的第二问）分层写，别只写「客户态度差」：
   - 产品价值被否（最想讲的差异化被当面禁掉，例如「今天不谈 AI，AI 不可控」）
   - 提问方式（只要是/不是、打断讲解、命令式「你现在就帮我搜一下」）
   - 评分表是否公允（明明判了无偏离又被当偏离项问）
   - **投入产出判断**（「这么多工具评审」+「才多少席位」= 他判断自己是陪标）← 这层才是火气真源
   - 个人处境（上一场会没结束、出差线上支持、本以为是「答疑」变成逐项审判）
4. **原话照抄**：双方最刺的那几句直接引用（「Jira 能做到，你做不到，就没有得聊」「你不要讲商务性的词，讲干货」）
5. 收尾给 **2 条可直接执行的动作**（例：把评估表拿回来按「真不支持 / 支持但需配置 / 需集成+插件」三档做书面应答）

## 3. 两条硬约束

- 🚨 **私聊吐槽 ≠ 会上发言**：同事私聊里的狠话和他对着麦克风说的（克制、还主动提议会后书面应答）是两件事，
  **分别标注**，不要合成「他当场发飙」。火气的**直接触发点**靠时间戳对齐指出（私聊 17:17 那句 ↔ 会上 17:16–17:17 那段追问）
- 🚨 **会议室麦归因说明**：若发言挂在会议室设备名下（`…F17-06🎦(8)`），按内容推断归属并在结尾显式声明不确定性
- **「这次没做到的 / 归因说明」照旧要写**（未授权 scope 拿不到某类记录、图片是局部截图右侧被裁等），不要用推断填空
