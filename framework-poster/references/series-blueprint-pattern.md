# 系列蓝图：把个人知识库压成 N 张可讲的一页纸图

> ⚠️ **这一版成品被用户否掉了，别照抄版式。** 用户原话：「好像不是很 OK……就都是文字，没有一些流转的效果」「现在全是文字都没有想看的欲望」。保留下来的只有**流程**和**提问顺序**（这两部分仍然正确，照用）；**版式和文案密度是反面教材**——改用 SKILL.md 的「闭环路径图」+ `templates/loop-poster.html`。
>
> 第二轮重做的三条修正：① 卡片拼段落 → SVG 圆+曲线+虚线回环；② 每格 30 字以内，全文 ≤300 字；③ 去掉全部业务口径（「用量超过 700 万」这类），换任何人能代入的说法。

一次真实交付（2026-11-09）。用户原话：「你看看我 obsidian 里的内容，有没有可以形成闭环的认知……以后我只要拿着这些图，就可以让别人能快速了解我的方法论或者认知。你不清楚的地方，可以每次问我问题，直到你达到 95% 以上的理解度之后再执行。」

产出：4 张 1240×~1300 一页纸图，主图 + 人的闭环 + 组织的闭环 + 交易的闭环。（**成品被否，见上方警告**）

## 流程（顺序别换）

1. **先扫库，别先问。** 35 篇 concepts，用一条 `find + wc -c` 按体积排序定优先级，再用 Python 批量打印每篇去 frontmatter 后的前 600 字。只把「压到底的那几条」读进来，不把 250KB 原文塞进上下文。
2. **降秩，给骨架，不给目录。** 35 个点压成三条线（人的尺度 / 组织的尺度 / 交易的尺度），并找到它们共用的那个发动机（本例是 Context not Control 的三层同构）。判断标准：这几条能不能把 35 篇逐篇倒回来。倒不回来的，说明少一根或少读了几篇。
3. **先交判断，再提问。** 把降秩结果用 30 秒能读完的篇幅陈述一遍（证明读懂了），然后只问一件真正会改变成品的事。
4. **一次一问，问题带推荐项。** 用 clarify，每轮一个问题、选项把推荐放第一。每答完一轮，把答案的影响说一句（「选人的线开场，图的开场就完全不同」），再问下一个。
5. **出图 → 自检 → 连发。**
6. **归档回知识库。** 建 `concepts/主题{最大编号+1}-xxx.md`（四段结构），图片放 `assets/{slug}/`，在 note 里用 `![[assets/.../p1.png]]` 嵌入，同步更新 `index.md`（顺手补缺失的旧条目）和 `log.md`，再 rsync 到镜像库。

## 三个问题（按这个顺序问最省轮次）

| 顺序 | 问题 | 为什么它必须在前 |
|---|---|---|
| 1 | 这些图主要给谁看 | 决定术语密度、案例要不要脱敏、语气。对客户 / 对内部 / 对听众，三种写法不通用 |
| 2 | 要哪种交付形态（4 张 / 1 张主图 / 只分图 / 先看草图） | 决定工作量与骨架深度，答完才能动手 |
| 3 | 总图的主线走哪条 | 决定开场第一句话。人的线开场是「我也不会」，组织线开场是「你们买了 AI 为什么没人用」，业务线开场是一个数字 |

问三个就够。第三问之后直接开工，不要再确认结构——结构已经在提问过程里被三句话锁死了。

## 四张图各讲什么

- **主图**｜三栏并列（人 / 组织 / 交易），栏间窄箭头写「晋升驱动」「用量数据」——这两个词是把三层焊住的螺丝。底部深色底座讲共用发动机，附 Control / Context / Environment 三格对照。结论条写「落地失败的多数不是模型不行」。
- **人的闭环**｜上半分岔（浅用收窄 vs 深用碾压，各给「三年后」一行），下半四步（换位置 / 换关系 / 换存法 / 换落点）+ 回流带 + 一条数字带（50-60% vs 90%+，token -90%，20/80）。
- **组织的闭环**｜阶段链三格（数字化基座 / AI Ready / AI Native，每格底部检查点）+ 公式条（涌现概率 = 环境触发 × 内在可燃性 × 首次成功体验）+ 四步环 + 风险链条 vs 三条解药。
- **交易的闭环**｜五步链 + 回流带 + 三条量化触发器 + 四个反例。

## 这一轮踩到的坑

- **竖排箭头标签**（`writing-mode:vertical-rl`）在 54–66px 窄列里读不成词，改成横排两行 `<div class="lb">晋升<br>驱动</div>`。
- **对齐靠眼睛判断必错。** 连续三次肉眼觉得四张卡差 15px，`scripts/measure.js` 实测 top/bottom/height 完全一致。凡是 flex + `align-items:stretch` 的行，高度天然相等，不用管。
- **短卡留白**：四栏里若有一栏文案明显短，`margin-top:auto` 会把底部结论推到很低、中间露出大洞。给短栏补一条要点，比改间距有效。
- **翻案句**：自己草稿里冒出「不是它变强了，是你把它养熟了」「这不是选工具，是搬大脑」这种句式，分布在结论条和卡片正文。写完搜「不是」「而是」逐个拆成两句。
