# 一页纸框架图（framework-poster）

把一段口头/文字分析压成**一张可转发的图**：结论先给、模块分层、客户能当场看。

## When to Use / 何时用、何时不用

- **用**：客户诊断结论、方法论框架、会后跟进材料、给老板/客户"一眼看到"的结构图。
- **不用**：
  - 情绪化阅读卡、小红书大字卡 → `ljg-card`（注意：它的模板带第三方作者 footer，客户材料不能直接交付）。
  - UI mockup / 落地页 / PPT → `baoyu-design`（流程重，要问一堆问题）。
  - 飞书原生画板 → `beautiful-feishu-whiteboard`。

## 为什么自建 HTML，不套现成模板

1. 对外材料不能带别人的品牌 footer。
2. 框架图结构每次都不一样（判据条 / 流程栏 / 分拣机 / 风险+解药），模板会逼你削内容。
3. HTML 到 PNG 全可控：字重、对齐、2x 清晰度；客户要改一个词，30 秒重出。

## 六步

0. **先分清通用版还是场景版。** 对外通用图不能直接搬自己的业务口径——产品名、价格档位、内部指标。真实翻车：图里写「用量超过 700 万」，没用过那个产品的读者完全接不住。换成任何人能代入的说法：那件事、那个人、那一堆自己的材料。用户会直接问「没用的企业怎么理解到这种」。
1. **先定主线一句话**——用户自己那句判断就是标题，别另起一个中性标题。
   例："别在每个环节加 Agent，先把流程切成「可判定」与「偏好型」"。
2. **选版式模块**（见下面 poster grammar），先画骨架再填字，不要边写边排版。
3. **复制 `templates/poster.html`**，替换内容；配色/字号体系保留，只改文字和色值。
4. **出图**：`node scripts/shot.js in.html out.png 1240 2`（宽 1240、2x → 2480px，A4 比例）。
5. **自检 → 交付**：见"自检"与"交付"两节，**自检必做**。
6. **一套多张时，先出 1 张定视觉语言。** 4 张一起盲做，风格被否就是 4 张全废（本 skill 真实发生过一次）。先交 1 张、把话问死（「这个视觉密度和风格对不对」），点头之后再按同一套批量出剩下的。

## Poster grammar（可复用版式模块）

| 模块 | 结构 | 作用 |
|---|---|---|
| 判据条 | 顶部深色卡：一个大问句 + 左右两个分支（各给"谁承接 + 干什么"） | 全图只回答一个问题，读者 5 秒抓住主线 |
| 分度栏 | 3–4 栏横向，每栏底部一根比例条 + 百分比 | 让"程度差异"可视化，比文字列表有说服力 |
| 分拣机 | 左一个原始输入（引语卡）→ 中部箭头 → 右侧两条通道（各给"进哪个库 + 后果"） | 把抽象边界落成一道可执行工序 |
| 风险 + 解药 | 左深色讲死亡螺旋（箭头链），右白底给 3 条带编号的机制 | 先制造痛感再给办法，客户不会只记住问题 |
| 结论条 | 底部深色：一句加粗结论 + 两行解释 | 决定这张图会不会被转发 |

每块给 `01/02/03` 编号，并在右上角加一句"这一栏为什么值得看"（如"这是企业唯一能攒下来的 AI 资产"）。

## 扩展版式：分岔 / 环路 / 链条（做方法论蓝图时用）

判据条适合「一个问题两个分支」。讲方法论、讲闭环时内容形态不是二选一，是分岔和环路，另建四个模块（类名照下面写，可直接复制改）：

| 模块 | 结构 | 什么时候用 |
|---|---|---|
| 分岔对比 `.branches > .br.bad/.br.good` | 左右两张深色卡，砖红 vs 墨绿，各三条特征 + `margin-top:auto` 一句「三年后」 | 讲两条路终点不同，先制造选择感 |
| 环路 `.loop > .node` + `.sarrow` + `.return` | 3–5 张卡横排 + 底部虚线回流带。**只在信息量确实压不下来时用**；讲「怎么一步步走通」一律改用下面的闭环路径图，卡片版会被嫌"全是文字" |
| 公式条 `.formula` | 深色窄条：左侧标签 + 大字号公式（乘号 `&times;`，因子用 `<u>` 上色且 `text-decoration:none`）+ 右侧一行注解 | 把整张图的判据压成一个式子 |
| 阶段链 `.chain > .stg` + `.ck` | 每卡底部 `margin-top:auto` 放检查点，`align-items:stretch` 自然等高 | 讲不可跳的阶段，让读者对号入座 |

配套两个窄条：触发器 `.trig`（三条正向信号，左侧 3px 墨绿边 + 大字数值）、反例 `.traps`（四条失败模式，`#FBEDE4` 底 + 砖红标题）。反例条通常比正向方法更抓老板，放在结论条正上方。

## 闭环路径图（讲方法论时的首选版式）

卡片版环路被真实用户整体否过一次，原话是「就都是文字，没有一些流转的效果」「全是文字都没有想看的欲望」。同样内容换成 SVG 图形后一次通过。判据只有一句：**结构由圆和线承载，卡片只装字。** 图形承载流转，文字承载细节，两者不能反过来。

做法（`templates/loop-poster.html` 是跑通的完整文件，改字即用）：

1. **五个节点，每个一个字。** 用单字动词（找 / 选 / 用 / 留 / 再），圆 `r=54` 填墨色、字 40px 反白。五个字排出来本身就是路径摘要，比任何小标题都记得住。
2. **一条曲线串起来，别用直线。** `M112,86 Q224,126 337,86 Q449,126 562,86 …`，圆压在线上，看起来是链条而不是并列卡片。
3. **其中一个节点换砖红**，标出整条路的关键动作（通常是第三或第四步）。全黑没焦点，全红没层次。
4. **虚线回环从外侧绕**，这是"闭环"两个字的唯一兑现点。走内容区左右两端（x=24 / x=1104），箭头水平指回第一个圆的侧边。
5. **每个圆下面固定三行**：标题（≤8 字）、注解两行（每行 ≤14 字）、一行"当天能做的动作"（11.5px 灰字）。
6. **卡点标注**压在两个圆的空隙上方，配一条 3px 虚线小竖线，文字 ≤7 字（「九成的人卡在这」这类），标在真正失速的那一步之前，不是第一步之前。

一页 5 个节点的总字数控制在 300 字以内。超过 300 字说明没降到位，回去砍，不要加字号。

## 多图系列（一张主图 + N 张分图）

用户要「拿给别人快速了解我的方法论」时，单张塞不下，走系列：

1. **一张主图定骨架**：三栏并列 + 栏间窄箭头 + 底部深色底座讲「共用的同一个发动机」。箭头标签用横排两行 `<div class="lb">晋升<br>驱动</div>`，**别用 `writing-mode:vertical-rl`**，竖排标签在 60px 窄列里挤成一团、读不成词。
2. **每张分图只讲一条线**：h1 是一句判断（「组织不是被培训点燃的」），不是分类名（「组织」）。每张自带一个分岔或公式 + 一个回流带。
3. **共用同一套色值和字号层级**，只换内容。系列感来自不变的部分。
4. **交付**：一条消息连发 N 个 `MEDIA:` 路径，跟的文字不是复述图上内容，是「讲的时候这张图怎么用」——先讲哪块、哪块会被追问、哪块别从头念。

完整的一次真实交付（4 张图：主图 + 人的/组织的/交易的闭环，含 clarify 提问顺序与归档步骤）见 `references/series-blueprint-pattern.md`。

## 海报文案和长文同一个标准

草稿里最容易犯的不是术语，是**翻案句**。小标题、结论条、「三年后」那一行最容易被写成「不是 A，而是 B」「不是 X，是 Y」。写完全图搜一遍「不是」「而是」「说白了」「真正的问题是」，命中就拆成两句直陈。冒号、破折号同样禁。

## 设计约束（都是踩过的坑）

- **CJK 断词**：固定 `max-width` 下中文会在词中断行（出现过 "AI，业 / 务流"）。→ 用显式 `<br>` 控制换行点，别指望自动折行。
- **不要改第三方模板的 footer/branding**：客户材料里出现别人的名字就废了，所以自建。
- **2x + fullPage**：`deviceScaleFactor=2`，高度由内容撑开（`document.body.scrollHeight`），别写死。
- **字号下限**：正文 12.5px、注解 11.5px（以 1240 宽为 1x 基准），再小手机上必须放大会烦。
- **配色**：纸白 `#F6F2EA` / 墨 `#1B1A17` / "可判定"墨绿 `#1B4A40` / "偏好"砖红 `#B4472A`。禁紫蓝渐变、禁纯黑、禁"三等分卡片凑数"。
- **数字优先**：写"影响 3 个环节、2 份提案、6 人日"，不写"影响很大"。形容词会让老板反感，数字不会。
- **文字密度硬上限**（2026-11-09 用户否掉一版四张图后的结论）：单张图的正文总量不超过 400 字，每个模块不超过 60 字。超过就不是海报，是排过版的文章。用户的评价原话是「全是文字，都没有想看的欲望」。
- **要流转，不要罗列**：多个模块之间必须有连接件——曲线、箭头、回路虚线、编号链。五个并列的卡片等于五块牌子，不是一条路。判据：站一米外看，能看出方向吗。
- 侧栏高度不齐时给容器加 `display:flex; flex-direction:column; justify-content:center`，别留一大片空底。
- **视觉锚点用符号不用字**：节点用一个大号汉字或一个几何图形做锚，比一堆小字更容易被记住（「找选 用 留 再」五个字串起来就是口诀）。

## 通用化检查（对外材料必做）

内部视角的口径会悄悄溜进图里，外部读者看不出来你在说什么，只会觉得跟自己无关。

三类必删：

| 类型 | 例子 | 换成 |
|---|---|---|
| 内部度量 | 「用量 700 万」「消耗率 2 倍」 | 量级词或比例：「额度快用完了」 |
| 内部流程名 | 「一把手站台」「用量测算表」 | 动作描述：「老板公开表个态」 |
| 内部角色 | RM / CSM / CAIO | 老板 / 负责人 / 具体岗位 |

判据一句话：把这段给一个完全外行的朋友看，他会不会反问「这是什么」。会反问，就是没通用化。
- **SVG `<text>` 标签内不留换行和缩进**：`<text …>` 后面换行再写文字，`text-anchor="middle"` 会整体偏移，标注压到隔壁圆上。一律写成一行的 `<text …>文字</text>`。
- **1240 宽塞 5 个 r=54 的圆，圆间空隙只有约 117px**：卡点标注这类批注必须 ≤7 字、`letter-spacing` ≤0.5，否则压到相邻圆顶。
- **回环虚线不能走节点正下方**：竖直段会穿过节点下面的标题和注解（实测箭头直接扎在「找一个点」四个字中间）。一律从内容区左右两端绕行，箭头水平指向第一个圆的侧边。

## 自检（Generator → Evaluator，必做）

出图后 `vision_analyze` 问三件事：
1. 有没有文字溢出 / 截断 / 重叠？
2. 哪里空、哪里挤？
3. 能不能直接当正式客户材料发出去？

**再问三件（2026-11-09 补，前三问查不出来的）：**

4. 站一米外看，这张图传达的是一个**动作或方向**，还是一堆信息？
5. 缩到手机屏宽，还能看出主线吗？看不出就是字太多，砍字，别调字号。
6. 有没有内部口径（7 位数金额、内部流程名、内部角色名）会让外行反问「这是什么」？

**对齐不要用眼睛判断。** 缩略图上极容易把等高卡片看成差十几个像素，然后来回改 CSS 做白工（本 skill 就发生过：眼看三次不等，实测四张卡 top/bottom/height 完全一致）。先跑 `node scripts/measure.js <file.html>` 打印每个卡片的真实几何，数值一致就不再动，只改真正不齐的那种。

不合格就改 CSS 重出，**最多 2 轮**（第 3 轮收益极低，先交付再按反馈改）。

## 交付

- 先发 `MEDIA:/绝对路径.png`，再跟 3–5 行文字：**每一块在图里起什么作用**（不是复述图上的字），最后给源文件路径 + 一句"要不要再出极简版 / 换客户配色"。
- 源 HTML 留在原处并告知路径，客户改词时只改 HTML 重跑 `shot.js`。

## 支持文件

- `scripts/shot.js` — HTML → PNG，自动定位 puppeteer-core 与 chromium。
- `scripts/measure.js` — 打印每张卡片的真实 top/bottom/height 并给出 ALIGNED / MISMATCH 分组汇总。判断对齐用它，别用眼睛看缩略图。
- `templates/poster.html` — 完整骨架（判据条 + 分度栏 + 分拣机 + 风险解药 + 结论条），已调好 CJK 字体与配色。
- `templates/loop-poster.html` — 闭环路径图骨架（5 个单字圆节点 + 曲线 + 外侧虚线回环 + 卡点标注 + 结论区）。讲方法论、讲「怎么一步步走通」时优先用它，改字即用。
- `references/example-ai-process-attribution.md` — 一次真实交付的完整论证骨架（客户 AI 流程改造的"可判定性归因"），做同类主题时直接复用结构。
- `references/series-blueprint-pattern.md` — 多图系列的真实交付记录：扫库降秩 → 三个 clarify → 归档回 Obsidian 的完整步骤。⚠️ 该轮**版式被否**，文件顶部已标注：流程和提问顺序照用，版式别抄。
